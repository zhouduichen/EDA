# 编辑器与逻辑仿真缺陷修复设计

## 目标

修复当前远端主分支中阻塞 GUI 编译、打开工程后继续放置元件、工程文件边界解析和新建菜单的问题；同时让已经打开的逻辑仿真窗口随电路模型变化刷新，避免显示过期的输入/输出列表。

## 范围

- 修正 `SimulationDialog` 中 `std::string` 与宽字符串混用导致的编译错误。
- 为元件工厂增加快照同步能力。打开或新建工程后，下一元件 ID、位号计数器和已使用位号与当前模型一致。
- 实现“文件 → 新建”，清空模型、选区、撤销/重做历史和半成品连线，并回到选择工具。
- 保持旧版 CSEPROJ 记录兼容，同时支持包含空格、引号和反斜杠的属性值；要求工程文件包含 `END`，拒绝重复/无效的组件和导线 ID。
- 仿真对话框在模型发生变化时重建输入/输出控件，按组件 ID 保留已有输入状态并立即重新计算。
- 补充元件工厂同步、工程格式边界和仿真回归测试。

## 设计方案

采用最小改动方案，不引入新的第三方库或重写工程格式。`IComponentFactory` 增加带默认空实现的同步钩子，避免破坏外部工厂实现；内置工厂实现按快照扫描最大 ID、位号数字后缀和已用位号集合。`EditorController::LoadSnapshot` 在替换模型后调用同步钩子，因此打开和新建共用同一条状态重置路径。

工程文件仍使用现有文本格式。保存属性值时，仅在值为空、包含空白、引号或反斜杠时加引号并转义；加载器用轻量行内 tokenizer 同时支持旧的无引号值和新的引号值。加载结束时必须看到 `END`，并在返回快照前校验 ID、必填字段、数值有限性和重复记录。

仿真核心求值算法保持不变，因为已有测试覆盖半加器、未知传播、门逻辑和多驱动冲突。仿真 UI 增加 `RefreshCircuit()`：保存现有输入复选框状态，销毁旧控件，按最新快照重新生成控件，然后再次调用现有 `Run()`；主窗口的模型变更回调负责触发刷新。

## 错误处理

- 编译错误通过显式 `wxString` 转换消除。
- 工程文件格式错误返回 `kInvalidFileFormat`，不调用 `LoadSnapshot`，避免破坏当前工程。
- 新建工程不弹出未保存确认，因为当前代码没有脏状态/当前文件路径模型；本次不扩大到文件管理功能。
- 仿真无输入、悬空输入和冲突驱动继续按现有 `0/X` 语义显示，不改变核心行为。

## 验证标准

- `cmake --build build -j` 成功构建 `cse_editor` 和 `cse_core_tests`。
- `ctest --test-dir build --output-on-failure` 全部通过。
- 回归测试确认：加载 `IN1` 后新放置元件得到 `IN2` 和下一个模型 ID；空格属性可保存并加载；缺失 `END`、重复 ID 被拒绝；仿真基础结果仍正确。
